# Splunk Scope v1.8 — Release Notes

**Release name:** UX & Reliability Hardening  
**App version:** 1.8.0  
**Schema version:** 3  

---

## Summary

v1.8 focuses on **UX clarity, reliability hardening, and developer infrastructure**. The Customer Intake page moves to a three-column layout for faster SE onboarding. All five known bugs from v1.7 are resolved. Error boundaries, a toast notification system, and Vitest are introduced. Theme inconsistencies are corrected and the report receives a stronger executive summary.

---

## Bug Fixes

1. **HomePage "Load Example" fixed** — Previously dispatched a bare string; now correctly imports the full scenario object with `{ intake, sources }`.
2. **Interpretation page stale analysis** — Now detects when intake fields change after analysis and shows a re-analyze prompt instead of serving stale results.
3. **Dead `migrationWarning` state removed** — The unused `useState` and context exposure are cleaned up.
4. **Unused `grouped` variable removed** from `UseCaseSelect.jsx`.
5. **Import failures now visible** — All session import errors surface via toast notifications instead of silent `console.warn`.

---

## New Infrastructure

### Error Boundaries
- App-level `ErrorBoundary` wraps the entire application in `main.jsx`.
- Page-level boundaries wrap each workflow page in `App.jsx`.
- Recovery UI with "Try Again" button instead of white screen on crash.

### Toast Notification System
- `ToastProvider` and `useToast()` hook in `src/components/layout/Toast.jsx`.
- Four tone levels: success, warning, error, info.
- Auto-dismiss with configurable duration.
- Integrated across: session import/export, scenario save/load/delete, reset, example load, template toggle, context apply.

### Vitest
- Vitest installed as dev dependency.
- `vitest.config.js` with Node environment.
- `src/services/engines.test.js` — 14 tests covering coverage, overlap, sizing, plans, migration, eligibility, and the Load Example bug fix.
- `npm test` script added to `package.json`.
- Existing 83 engine tests continue to pass via `node src/tests/engineTests.js`.

---

## UX Improvements

### Customer Intake Page (main visual rework)
- **Three-column layout** on desktop:
  - Left: Customer name, deployment type, discovery notes.
  - Center: Use cases, Splunk apps, custom goals.
  - Right: Maturity goals (crawl/walk/run), import context, session tools.
- **Quick Start collapsed** by default with active indicator.
- **Session tools** (export, import, reset) accessible directly on the intake page.
- Deployment type buttons use theme accent tokens instead of `--cast-green`.

### Interpretation Page
- **Stale analysis detection**: shows warning banner with "Re-analyze" button when intake changes after analysis.
- `handleReanalyze()` function recomputes interpretation from current intake.

### Report Page
- **Executive summary** rewritten to be more business/customer-oriented: describes what the path provides, coverage achieved, ingest ranges, and remaining gaps.
- **Architecture Path** and **Use Cases** sections default to open for a stronger first impression.
- Expanded sections show meaningful content rather than appearing empty.

### Architecture Paths Page
- Already 3-column on desktop (`lg:grid-cols-3`); confirmed working.
- Cost level badges now use theme tokens instead of literal Tailwind color classes.

---

## Theme Consistency

Replaced all literal Tailwind color classes (`bg-green-900/20`, `text-green-400`, `bg-blue-900/20`, etc.) with CSS custom property references:
- `SourceWorkflowPage.jsx` — `CONF_BADGE` map.
- `SourceInfoModal.jsx` — `STRENGTH_COLORS` map and dependency status badges.
- `PlansPage.jsx` — cost level badge classes.
