# Splunk Scope v1.7 — Release Notes

**Release name:** Sizing Intelligence & Source Catalog Hardening  
**App version:** 1.7.0  
**Catalog / schema:** 1.7 (see `src/data/catalogVersion.json`)  

---

## Summary

v1.7 expands Splunk Scope’s **sizing intelligence** and **source catalog governance**. The release introduces a structured low/average/high model across the sizing dataset, vendor- and model-aware adjustments, explicit counting methodology for workshop conversations, and richer mappings between sources, use cases, and log capabilities—backed by research notes and validation metadata.

---

## Highlights

### Expanded sizing rates

- Sizing rate entries grew from roughly **15** to **~94** distinct sources in `sizingRates.json`, each with **low / medium / high** GB/day bands per defined unit where applicable.

### Vendor and model framework

- **Vendor/model-specific sizing data** for **13** categories in `vendorModelRates.json` (multiplier bands per major vendor).
- **`vendorRates` and nested `models`** in `sizingRates.json` for applicable sources (full **model-level** rate tables are richest for categories such as **firewalls** and **EDR**; other categories may use vendor-tier or category multipliers first).

### Source counting methodology

- `sourceCountingMethods.json` documents **how to count** each source (primary unit, customer questions, common mistakes) for consistent SE workshops.

### Use-case mappings

- `sourceUseCaseMappings.json` ties **all 53** top-level catalog sources to relevant use-case context.

### Log capability mappings

- `sourceLogCapabilities.json` describes produced capabilities, CIM/datamodel alignment notes, and related metadata for **30+** sources.

### Research notes and validation status

- `sizingResearchNotes.json` captures **33** source-level research summaries (sources consulted, assumptions, limitations, review timestamps).

### Documentation

- **`docs/SIZING_METHODOLOGY.md`** — how bands, units, multipliers, overrides, and review flags should be interpreted.
- **`CHANGELOG.md`** — version-to-version summary at repository root.

### Dataset governance

- **`catalogVersion.json`** centralizes `appVersion`, `sourceCatalogVersion`, `sizingRatesVersion`, and `useCaseMappingVersion` with a change summary for traceability across JSON artifacts.

### Schema migration

- **Session / local state** migrates to **`schemaVersion` 3** (`CURRENT_SCHEMA_VERSION` in `sessionMigrationEngine.js`), including migration steps from prior versions.

### New and expanded configuration data

- **15+** new or materially expanded data artifacts ship with v1.7 (including dedicated JSON catalogs for sizing, vendor/model rates, counting methods, use-case mappings, log capabilities, research notes, and version governance—plus coordinated updates across existing requirement and catalog files).

---

## Bug fixes and reliability

- **CoveragePage** — corrected **variable ordering** issues that could affect render-time behavior or computed values.
- **Missing function** — resolved reference to **`rowCountsTowardTotals`** (aligned with `sourceCountsTowardTotals` / eligibility helpers).
- **Theme toggle** — fixed **icon direction** / display for light/dark switching.
- **planEngine** — **buffer** handling fix so plan totals respect configured buffer semantics consistently with the sizing pipeline expectations.

---

## Operational notes for SEs

- Treat all GB/day values as **planning estimates**; validate with customer-specific metering where commitments matter.
- Sources flagged **`needsReview: true`** in `sizingRates.json` warrant extra validation—see `docs/SIZING_METHODOLOGY.md`.
- Storage and retention sizing remain a **separate** exercise from daily ingest; see methodology doc for guidance.
